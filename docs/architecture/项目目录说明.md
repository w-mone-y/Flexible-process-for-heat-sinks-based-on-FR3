# 项目目录说明

本文档描述整理后的仓库结构。目标是让根目录只承担“项目入口”职责，把代码、场景、
资产、配置、文档、测试和运行输出分别放到稳定边界中。

## 根目录

| 路径 | 职责 |
|---|---|
| `README.md` | 项目总览、截图、快速启动和能力说明。 |
| `LICENSE` | 项目许可证。 |
| `Makefile` | 安装、格式、测试与 headless 验证命令。 |
| `pyproject.toml` | Python 包、依赖和开发工具配置。 |
| `brazing_line.py` | 标准版兼容启动器；真实实现位于 `brazing_sim/cli/line.py`。 |
| `brazing_line_v2.py` | 双安装支路 V2 入口；与 V1 使用独立 MJCF 和运行时。 |
| `brazing_line_cinematic.py` | 精细视觉版兼容启动器。 |
| `run_flexible_order.py` | YAML 柔性订单兼容启动器。 |

根启动器刻意保持很薄，因此原有命令不变，业务实现不会继续堆积在根目录。

## 核心代码：`brazing_sim/`

```text
brazing_sim/
├── cli/                CLI、Viewer/headless 主循环与柔性订单入口
├── dual_line/          V2 拓扑、领域状态、场景适配与机器人动作投影
├── changeover/         工装配置差分、序列相关换型矩阵与 KPI
├── execution/          Arm1/2/3、工位、输送和物流物理技能
├── experiments/        事件指标、报告导出和调度对比
├── flexible/           YAML 加载、产品几何、工装和 ProcessPlan
├── planning/           ManufacturingTask、TaskGraph 和运动规划
├── recovery/           故障模型、恢复策略、重试和重规划
├── scheduling/         固定/动态调度、资源与区域锁
├── paths.py            项目根、场景、配置、资产和输出目录
├── flexibility_report.py
├── manufacturing_runtime.py
├── motion.py
├── scene.py
├── fixture.py
├── inspection.py
├── batch_transfer.py
└── api.py / ui.py
```

重要修改入口：

| 需求 | 首选文件 |
|---|---|
| 改订单字段或产品状态 | `domain.py`、`flexible/models.py` |
| 改 A/B/C 几何或路径 | `flexible/geometry.py`、`config/products/` |
| 改 Arm1/2/3 物理动作 | `execution/async_line_skills.py` |
| 改 V2 双支路布局或动作 | `dual_line/topology.py`、`dual_line/scene_adapter.py` |
| 改托盘、炉体或成品物流 | `execution/async_line_logistics.py`、`batch_transfer.py` |
| 改任务依赖 | `planning/task_graph_builder.py` |
| 改动态派工 | `scheduling/` |
| 改故障恢复 | `recovery/`、`fault_visuals.py` |
| 改 UI/API | `ui.py`、`api.py` |

## 场景：`scenes/`

```text
scenes/
├── production/
│   ├── brazing_line.xml
│   ├── brazing_line_v2.xml
│   ├── brazing_line_cinematic.xml
│   └── assets -> ../../assets
└── includes/
    └── cinematic_equipment_detail.xml
```

`production/assets` 是指向仓库 `assets/` 的相对符号链接。MuJoCo 展开嵌套
`include` 时会以顶层 XML 目录解析部分资产路径；该链接保证标准版和精细版共享同一份
FR3、网格和铭牌，不复制资产。

## 资产：`assets/`

```text
assets/
├── robots/fr3/         正式 FR3 XML、必要网格、图片与上游许可证
├── signs/              项目自制中文设备铭牌
└── meshes/             项目自制展示网格
```

未被当前钎焊主线引用的 Panda、KUKA iiwa、UR5e、旧抓取示例、试验手爪模型和整链节
重复网格已经删除。FR3 正式 `fr3.xml`、它实际引用的视觉/碰撞网格，以及上游
`LICENSE`、`README`、`CHANGELOG` 和 `scene.xml` 一起保留。

## 测试、基准与运行输出

```text
tests/
├── shared/             跨版本领域模型测试
├── v1/                 标准线、柔性订单、物理 actor 与旧入口回归
└── v2/                 双安装线、拓扑、场景、调度、API/UI 与门控回归

benchmarks/
├── compare_versions.py 可复现 V2 / V1 / 早期 V1 对照运行器
└── results/             精选 JSON、CSV、Markdown 和 SVG 证据
```

- `make test-v1` 与 `make test-v2` 可分别执行两条版本线；`make test` 仍运行全部测试。
- `benchmarks/results/` 只保存经过说明的精选实验快照；一般临时实验仍写入 `artifacts/`。
- `artifacts/`：实验 CSV、JSONL、日志、截图和报告的统一本地输出目录。
- `artifacts/`、`tmp/`、缓存、构建目录和 `*.egg-info` 均被 `.gitignore` 排除。

可再生输出不进入 GitHub。需要长期保存的证据应人工精选到 `docs/images/`。
