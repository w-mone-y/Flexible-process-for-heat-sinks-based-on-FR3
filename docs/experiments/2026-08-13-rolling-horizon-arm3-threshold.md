# 滚动时域与 Arm3 动态启用阈值验收

## 范围

- 不改变 MuJoCo 工位、机械臂和运输路线；仅增加无碰撞的 S1 库存主板显示。
- 在安全任务边界比较 Arm1 吸盘/夹爪动作与 V2 双安装支路。
- Arm3 仅在安装收益扣除检测等待、合流和 S4 阻塞后仍达到阈值时启用。
- 检测优先；已经开始的单片翅片安装保持不可抢占。
- 候选数上限为 4，Arm1 视窗 36 s，安装分支视窗 45 s；候选按 ID 确定性排序。
- 当前范围只覆盖 Arm1 吸盘/夹爪选择和 Arm1/Arm3 安装分支，不包含 S1 订单释放、
  炉批形成或合流顺序的多步全局搜索。

## 基线结论

固定点 `8de20e9` 在同一环境和命令下得到与上表相同的 makespan、吞吐、Arm1/Arm3
利用率、空闲时间和换刀次数。因此本轮实现可确认：

- 五类六订单场景无回退，且 Arm1/Arm3 各承担 3 个安装托盘。
- Arm3 的检测等待、下游堵塞和净收益已形成一致的可解释决策，且 reset 不泄漏旧决策。
- 不能宣称已经带来 makespan 或利用率提升；预设的 `5%` 提速目标未达成。

下一轮若以量化提速为目标，应扩大滚动时域动作集，优先把 S1 订单释放、炉批形成和共享
合流顺序纳入同一决策，而不是继续降低 Arm3 启用阈值。

## Arm1 主板波次与 S1 自动补料

- V2 统一运行时启用 Arm1 工具策略，但不启用旧 `flexible_cell` 物理
  状态机；V1 继续使用原有两件微批配置。
- 主板波次不再按订单总数硬编码。策略从可执行翅片资源推导
  `安装支路数 + 1 个上游缓冲`；V2 的 Arm1/Arm3 双支路因此先连续完成三块主板，
  随后立即释放翅片瓶颈。首个翅片波次启动后改为单块主板补位，避免安装台已有托盘时
  又重新积攒三块主板。
- Arm1 对当前已接纳 WIP 波次优先保持吸盘，S1 有可执行主板或下一块能在 12 s
  短视窗内到达时，不为普通翅片任务提前换夹爪。
- 当下游占用导致下一主板无法到达 S1 时，允许 Arm1 先安装翅片释放通道，避免为了
  “六块主板全部先做”导致工位环路死锁。
- S1 供料架增加无碰撞的库存板：运动代理取走时库存板隐藏，释放到托盘后立即补回，
  因此不会重叠闪烁，静态和订单间隔也始终可见。

Issue #26 将四主板强制波次替换为能力驱动的三主板首波与单主板补位，并修复
“Arm3 接下自己的翅片任务会错误清零 Arm1 主板波次”的状态迁移；同时让物理预定位
服从统一调度器的换刀意图，不再用第二套 12 s 规则重复拦截。`ABCABC` 从 `239.35 s`
降至 `237.35 s`，缩短 `2.00 s`（`0.84%`），吞吐率从 `0.025068` 提高到
`0.025279 件/s`（约 `0.84%`）。Arm1 换刀仍为 `3` 次，两支路仍为 `3 / 3`。
该结果等于固定点 `8de20e9` 的历史最短值；因此可以确认修复没有以牺牲节拍为代价，
但不能宣称超过历史最优。强制六块主板全部先行会将 makespan 恶化至 `271.55 s`，
两块短波则为 `266.05 s`，均未采用。
同一完整回放中，“S2A 托盘已停稳但 Arm2 仍空闲”的持续窗口为 `0`；
Arm3 仍按检测优先和预测空窗执行。
