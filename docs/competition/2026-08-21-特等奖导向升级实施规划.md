# FR3 柔性钎焊产线特等奖导向升级实施规划

> 版本：1.0  
> 制定日期：2026-08-21  
> 目标节点：2026-09-15 竞赛提交  
> 适用范围：V2 双安装线、统一制造运行时、调度与规划、实验和竞赛材料  
> 项目约束：现阶段限定为 MuJoCo 仿真，不引入强化学习，不新增机械臂，不重构已经稳定的 V1

## 1. 文档目的

本规划用于把当前“功能完整、场景丰富、能够并行执行”的 MuJoCo 柔性钎焊产线，升级为一套能够经受竞赛答辩追问的自主决策系统。

升级后的作品必须同时回答四个问题：

1. 系统为什么在此时选择这张托盘、这台机械臂和这条工艺路线？
2. 该选择与小规模最优解相比究竟相差多少？
3. 多机械臂并行运动为什么是安全的，而不只是“这次没有撞上”？
4. 效率提升究竟来自调度算法、资源柔性还是物理场景变化？

本规划不是继续扩建场景的清单。后续工作以算法、证据、安全和可解释性为主，视觉改动只服务于决策展示和实验复现。

### 1.1 实施状态（2026-08-22）

| 阶段 | 状态 | 当前证据 |
|---|---|---|
| Phase 1 影子数字孪生 | 核心完成 | 不可变快照、稳定指纹、真实事件驱动时长估计及测试 |
| Phase 2 CP-SAT 参照层 | 门禁完成 | 1～6 件旁路求解、独立校验、objective/bound/gap 与复现命令 |
| Phase 3 在线调度影子比较 | 门禁完成 | 确定性短窗口、拒绝解释、CP-SAT gap 和复现命令 |
| Phase 4 V2 权威派工 | 核心完成、效率目标待优化 | 双重门控、原子提交、事件触发、确定性回退和实际 MuJoCo 对照 |
| Phase 5 几何安全屏障影子模式 | 下一阶段 | 尚未接管真实几何碰撞查询 |

Phase 2 的实现范围和未建模边界以
[CP-SAT 最优参照规划规格](../specs/cp-sat-reference-planning.md)为准；Phase 4 的权威边界以
[TwinShield-RH V2 权威派工规格](../specs/twinshield-v2-authority.md)为准。当前状态不代表
几何安全屏障或驾驶舱已经完成。

## 2. 当前基线

### 2.1 已有能力

当前项目已经具备以下竞赛基础，不应重复建设：

- 三台 FR3 和超过三道制造工序；
- V1 浅 U 形单安装线和 V2 双安装线两个独立入口；
- A/B/C 产品、多订单队列、优先级、交期和紧急插单；
- 六套托盘、双翅片安装支路、三层贯通式批次炉；
- `ProcessPlan`、任务 DAG、READY 释放、资源与区域预留；
- Arm1/Arm3 翅片安装资源选择；
- 动态 WIP、滚动窗口、动态优先级和 Arm1 换刀策略；
- 可注入物理故障、实体返工、复检和人工处置；
- Viewer/headless 共用统一运行时；
- V1/V2、调度、故障和柔性化实验工具。

### 2.2 已有实测证据

| 场景 | 现有结果 | 结论 |
|---|---:|---|
| A/B/C 动态调度 | makespan 下降 31.77% | 动态释放和资源竞争决策有效 |
| A/B/C 各两件，V2 对 V1 | makespan 下降 47.0% | 双支路和异步流水显著提高吞吐 |
| 同族排序 | makespan 下降 8.70% | 顺序相关成本值得进入调度目标 |
| 自动恢复对 10 s 人工处置 | 节拍改善 12.74% | 自动返工闭环具有效率价值 |
| Arm1 + Arm3 双安装 | 当前样本反而增加 1.82% | Arm3 检测与安装冲突尚未被充分优化 |

最后一项是重要发现：增加资源不等于自动提高整线效率。新调度器必须优化整线流动，而不是追求每台机械臂表面上的忙碌率。

### 2.3 当前主要缺口

1. 在线调度主要是单候选评分和有限深度 Beam Search，缺少小规模最优参照。
2. 工序时间主要来自静态配置，尚未根据实际执行结果形成在线估计闭环。
3. V2 尚未完整消费能力延迟绑定和 AND/OR 替代路线。
4. PRM/RRT 规划服务仍使用恒真碰撞函数，逻辑分区预约不能替代真实几何校验。
5. 现有实验以少量固定种子为主，缺少置信区间、最优性差距和系统消融。
6. UI 能展示产线状态，但尚未形成面向答辩的自主决策驾驶舱。

## 3. 总体目标

项目技术主线暂定为：

> **TwinShield-RH：面向动态订单与扰动的数字孪生滚动时域安全调度方法**

该名称是工作名称，最终可在技术报告定稿时调整。核心不是命名，而是以下四层必须真实存在并能够独立验收：

1. **最优参照层**：CP-SAT 为小规模问题提供最优或有界参考计划。
2. **在线决策层**：事件触发的滚动时域算法在严格时限内完成资源、顺序、路线和批次决策。
3. **安全屏障层**：MuJoCo 真实几何、工具和载荷参与路径校验与时空预约。
4. **孪生反馈层**：实际工序时间、阻塞、故障和资源状态持续修正后续预测。

### 3.1 竞赛版成功定义

竞赛版只有同时满足以下条件才视为完成：

- 同一订单与随机种子下，算法结果可复现；
- V1 行为和回归测试不被破坏；
- V2 只由 `ManufacturingRuntime` 推进逻辑任务；
- 在线方案能够报告相对 CP-SAT 参照的最优性差距；
- 关键自由运动段经过真实 MuJoCo 几何碰撞验证；
- 多订单、紧急插单、资源冲突和代表性故障均能触发可解释的重规划；
- 完整实验报告包含多种子统计、消融实验和原始事件数据；
- UI 能让非代码评委看懂“发生了什么、系统为何这样决策、结果是否更好”。

## 4. 范围与非目标

### 4.1 本轮必须完成

- 冻结并可复现当前基线；
- 建立统一数字孪生状态快照和决策事件；
- 实现 CP-SAT 小规模参照求解器；
- 升级在线滚动时域调度；
- 建立 MuJoCo 几何碰撞查询和安全屏障；
- 接通 V2 的真实能力绑定与可执行替代路线；
- 增加决策驾驶舱和实验导出；
- 完成统计实验、消融和竞赛材料。

### 4.2 明确不做

- 不引入强化学习或多智能体强化学习；
- 不新增第四台机械臂；
- 不重新设计当前 V2 物理布局；
- 不恢复已撤销的实体自动换型龙门；
- 不用瞬时显隐或状态跳变冒充实体工序；
- 不重写 FR3 底层控制器和已经稳定的工艺轨迹；
- 不为了提高机械臂利用率而释放会造成下游阻塞的任务；
- 不把规划预估时间当作物理完成证据；
- 不在缺少统计证据时宣称“全局最优”或“工业级安全”。

### 4.3 可选加分项

只有核心验收全部通过后再考虑：

- MES/OPC UA 风格的只读订单与状态适配接口；
- 比赛演示脚本和自动镜头；
- 对 CP-SAT 计划进行轻量模仿学习，作为未来工作而非主流程；
- 更多产品配置，但不得突破实体对象池和物理尺寸边界。

## 5. 目标架构

```text
订单 / 紧急插单 / 故障 / 资源状态 / 物理完成事件
                         │
                         ▼
                DigitalTwinSnapshot
        ┌────────────────┼────────────────┐
        │                │                │
        ▼                ▼                ▼
 DurationEstimator   CP-SAT Reference   Feasibility Builder
        │                │                │
        └────────────────┼────────────────┘
                         ▼
               TwinShield-RH Scheduler
                 候选计划 + 成本分解
                         │
                         ▼
         Geometric Safety Shield / Reservation
                         │
              原子提交首个安全决策窗口
                         │
                         ▼
 ManufacturingRuntime → Physical Skill → MuJoCo
                         │
                         └──── 实际反馈闭环 ────┘
```

### 5.1 权威边界

- `ManufacturingRuntime` 继续是任务状态、READY 释放和完成状态的唯一逻辑权威。
- CP-SAT 和在线调度器只产生计划建议，不直接修改任务或 MuJoCo 状态。
- 安全屏障只批准、延迟或拒绝计划，不伪造任务完成。
- 物理技能继续使用非阻塞 `start → update/poll → cancel` 契约。
- 只有包含 MuJoCo 反馈证据的完成事件才能推进任务图。

### 5.2 决策时机

禁止每个仿真步执行完整优化。仅在以下事件发生时重规划：

- 新订单或紧急订单加入；
- 任务真实完成；
- 检测发现故障并插入返工链；
- 机械臂、相机、工位或炉层状态改变；
- 预测完成时间偏差超过阈值；
- 下游阻塞或上游饥饿达到阈值；
- 当前承诺窗口结束。

已经开始的物理动作不抢占。新计划只作用于尚未提交的任务和下一个安全动作边界。

## 6. 核心领域模型

### 6.1 `DigitalTwinSnapshot`

每次调度使用不可变快照，至少包含：

- 当前仿真时间和计划版本；
- 每个产品单元的订单、托盘、工位、工艺阶段和质量状态；
- 已完成、RUNNING、READY、PENDING 和返工任务；
- Arm1/Arm2/Arm3 当前工具、姿态、任务和预计释放时间；
- 工位、运输路线、合流区、炉口、炉层和输出区占用；
- 当前炉批、配方兼容性、等待时间和交期风险；
- 有效空间预约及其占用时间窗；
- 工序时长估计、方差和数据样本数；
- 已确认故障、恢复尝试和人工处置状态。

快照只读。调度器不得持有运行时可变对象的引用。

### 6.2 `PlanProposal`

调度结果至少包含：

- 候选任务与资源绑定；
- 预计开始、结束和工位占用；
- 运输与空间预约；
- 工具切换和顺序相关设置成本；
- 炉批选择；
- 总成本与各项成本分解；
- 约束违反列表；
- 相对参考计划的 gap；
- 计划生成耗时、超时和回退信息；
- 本次可以原子提交的承诺窗口。

### 6.3 新增统一术语

实现前应把以下术语补入 `CONTEXT.md`：

- **数字孪生快照**：调度时刻不可变的产线事实集合。
- **参考计划**：CP-SAT 在给定时限内产生的最优或有界计划。
- **承诺窗口**：重规划后允许立即执行且不会被本轮再次改变的任务前缀。
- **安全屏障**：在计划提交前验证碰撞、净空、预约和互锁的最后门控。
- **认证等待姿态**：允许机器人安全暂停并重新规划的离散姿态。
- **最优性差距**：在线方案目标值相对 CP-SAT 最优值或下界的差距。

## 7. 工作流 A：基线冻结与观测体系

### A1. 建立竞赛基线标签

- 记录当前提交、脏工作树和运行环境；
- 不覆盖用户现有未提交改动；
- 在干净提交后建立竞赛基线标签；
- 保存 A、A/B/C、六订单和代表性故障的原始事件日志。

### A2. 统一事件模式

为以下事件建立稳定 schema：

- 订单到达与接纳；
- 产品单元释放；
- 任务 READY、开始、阻塞、完成、失败和取消；
- 资源绑定、换刀、工位和路线预留；
- 物理动作反馈；
- 故障形成、检测、返工和复检；
- 炉批锁定、开始和卸载；
- 重规划触发、候选、选择和回退。

### A3. 验收

- Viewer 和 headless 输出相同语义事件；
- 相同种子重复运行得到相同任务结果；
- 每个产品单元能够从事件日志重建完整生命周期；
- 任意任务状态变化都能追溯到触发事件。

## 8. 工作流 B：在线时长估计与孪生反馈

### B1. 分层时长模型

按以下键维护执行统计：

```text
(task_type, resource_id, product_family, route_strategy, tool_state)
```

第一阶段采用确定性、可解释的方法：

- 初始值来自现有配置节拍；
- 使用指数滑动平均更新均值；
- 使用稳健残差估计波动；
- 样本不足时回退到工序级或全局默认值；
- 故障与人工处置样本单独统计，不能污染正常工序时间。

### B2. 预测输出

每个候选任务输出：

- 期望工期；
- 保守工期；
- 数据置信等级；
- 本次预测相对静态配置的变化原因。

### B3. 验收

- 新模型关闭时完全复现当前静态节拍行为；
- 估计值只消费真实完成事件；
- 多次运行后同类工序预测误差下降；
- 预测更新不会改变物理动作本身。

## 9. 工作流 C：CP-SAT 最优参照层

### C1. 建模对象

小规模柔性作业车间模型至少包含：

- 产品单元与工序；
- 工序优先关系；
- 可选机器人和可选工艺路线；
- 机器人、工具、工位、运输路线和共享区域互斥；
- 顺序相关工具/产品设置时间；
- WIP 与有限缓冲；
- 炉批容量、配方兼容性和不可拆分周期；
- 交期、优先级和紧急订单；
- 已开始任务固定、已完成任务锁定。

### C2. 变量与约束

建议使用：

- 工序开始与结束时间变量；
- 资源可选 interval；
- 路线选择布尔变量；
- 资源、工位和区域 `NoOverlap`；
- 工序 precedence；
- 批次分配和兼容约束；
- 已承诺任务固定约束；
- 托盘唯一所有权和运输先后约束。

### C3. 目标函数

优先采用分层或归一化加权目标：

1. 禁止违反硬安全与工艺约束；
2. 最小化加权延期；
3. 最小化 makespan；
4. 最小化下游阻塞与运输等待；
5. 最小化工具切换和产品设置；
6. 在前述目标相同时减少不必要的资源空转。

资源利用率不能成为压倒整线目标的主目标。

### C4. 运行方式

- 1～6 个产品单元：争取求得最优解或可报告 gap 的解；
- 更大队列：只求滚动窗口内任务；
- 严格限制求解时间；
- 超时必须返回当前最好解、下界和 gap；
- OR-Tools 不可用或模型失败时自动回退到当前调度器。

### C5. 验收

- 单件和简单串行场景与手工可验证结果一致；
- 不产生资源重叠、越过前驱或不兼容混炉；
- 3～6 件标准场景能够输出可验证计划和 gap；
- 求解结果可由独立计划校验器重新验证；
- CP-SAT 不直接推进运行时。

## 10. 工作流 D：TwinShield-RH 在线调度器

### D1. 可行候选生成

候选任务必须同时满足：

- 所有前驱和质量门控通过；
- 任务处于 READY；
- 资源能力、工具和参数窗口匹配；
- 工位、路线和下游容量可预留；
- 炉批兼容；
- 不违反 Arm3 检测优先和单片安装不可抢占；
- 不会破坏已提交承诺窗口。

### D2. 滚动窗口

第一版建议：

- 时间窗口：45～90 s 仿真时间；
- 任务窗口：未来 8～16 个可行任务；
- Beam Search 保留为确定性快速候选生成器；
- CP-SAT 参考计划用于估计关键路径和校准成本；
- 只提交第一个安全并行任务集合，其余计划随事件滚动更新。

### D3. 成本模型

每个候选计划至少计算：

```text
J = w1·预计完工
  + w2·加权延期
  + w3·关键路径延迟
  + w4·下游阻塞
  + w5·上游饥饿
  + w6·工具/产品设置
  + w7·运输和空间预约等待
  + w8·执行风险
```

所有分量必须使用同一量纲或经过归一化，UI 必须显示实际使用的分量。

### D4. Arm1/Arm3 特殊决策

- Arm3 检测任务即将释放时，不把它分配给长时间翅片安装序列；
- Arm3 已开始单片安装时不抢占；
- Arm1 是否换刀由未来主板任务、未来翅片任务、换刀成本和等待风险共同决定；
- 不因为 Arm1 暂时空闲就执行会堵塞 S2A/S2B 的提前上料；
- 若 Arm1 安装是全局瓶颈，优先保障其材料、工具和安全路径；
- 双安装只有在减少整线预计完工时间时才启用。

### D5. 原子提交

一个并行任务集合只有在以下资源全部预留成功后才能提交：

- 执行机器人；
- 工具和工位；
- 托盘当前所有者与目标所有者；
- 运输路线和合流区；
- 共享检测与炉口；
- 空间时间预约。

任一预留失败必须整体回滚，不允许部分任务先移动。

### D6. 回退策略

按以下顺序回退：

1. 缩短窗口重新规划；
2. 使用确定性 Beam Search；
3. 使用现有动态优先级；
4. 任务保持 READY 并给出明确阻塞原因。

禁止把规划失败直接转换为订单 ERROR。

### D7. 验收

- 在线决策 p95 小于 50 ms，最大值目标小于 200 ms；
- 超时后能够确定性回退；
- 多订单中不出现无限饥饿；
- 紧急订单不抢占当前物理动作，但获得下一可行释放机会；
- 复杂六订单场景相对当前动态基线的平均 makespan 目标下降至少 10%；
- 简单单件场景不得出现超过 3% 的节拍回退。

## 11. 工作流 E：MuJoCo 几何安全屏障

### E1. 迁移原则

安全屏障分两阶段接入：

1. **影子模式**：只检测和记录，不阻断现有物理流程；
2. **强制模式**：影子结果稳定后，才允许其延迟或拒绝计划。

已经调好的取放、涂覆、检测和翅片插装工艺轨迹不立即替换。第一阶段重点校验自由运动、跨工位运动和多臂共享空间。

### E2. 碰撞查询器

替换 `always_collision_free`，查询至少覆盖：

- 当前机器人全部连杆；
- 当前末端工具；
- 携带的基板或翅片；
- 其他机器人当前与预测姿态；
- 工位、换刀架、梳齿、压片、托盘和输送结构；
- 物流托盘的完整载荷包围盒。

工艺允许接触必须通过白名单显式声明，例如吸盘与基板、夹爪与目标翅片。白名单不得按整个机器人或整个工位粗粒度关闭碰撞。

### E3. 连续路径校验

- 关节路径按时间和空间双重阈值插值；
- TCP 空间采样间距不超过 10 mm；
- 时序检查间隔不超过 20 ms；
- 记录每条路径的最小预测净空；
- 预测净空低于 40 mm 时优先减速、等待或绕行；
- 实际非预期接触仍触发安全停机。

### E4. 时空预约

预约对象从逻辑工位单元升级为：

- 连杆扫掠包络；
- 工具包络；
- 载荷包络；
- 运输托盘包络；
- 共享合流、S4、炉口等强互斥区。

等待只允许发生在认证等待姿态。涂覆、下降放置、携带工件通过公共区时不得随意停住。

### E5. 验收

- 所有竞赛订单中非白名单接触为 0；
- 关键自由运动段预测最小净空不低于 40 mm；
- 动态障碍能够触发等待或重新规划；
- 路径预约完成、取消、故障和 reset 后全部正确释放；
- 安全屏障关闭时只用于对照实验，正式演示始终开启。

## 12. 工作流 F：V2 能力与替代路线闭环

### F1. 能力延迟绑定

V2 的物理运行时必须消费：

- `config/capabilities.yaml`；
- 产品参数；
- 路线能力需求；
- V2 产线执行剖面；
- 当前资源、工具和工位状态。

### F2. 替代路线

只接入具有真实 V2 actor 的路线。每个 Alternative 必须：

- 产生相同工艺效果；
- 有可执行资源和物理技能；
- 有明确节拍、风险和资源占用；
- 能被在线调度器比较；
- 能在任务图和决策解释中追踪。

没有实体执行能力的分支继续明确标记为规划态，禁止在演示中假装完成。

### F3. 自定义产品边界

- A/B/C 保持完整物理执行；
- D 和合法自定义订单先通过物理对象池、梳齿槽数、路径数量和尺寸校验；
- 通过全部物理校验后才允许进入 V2；
- 无实体模块、超容量或越界路径在计划阶段拒绝，不改变 MuJoCo 场景。

### F4. 验收

- Arm1/Arm3 绑定原因和排除原因可解释；
- Alternative 的选择能够改变真实物理执行者或真实工艺节点；
- 无候选时保留原绑定并告警，不生成无人执行的任务；
- 新产品不能通过放松物理约束获得“柔性”。

## 13. 工作流 G：自主决策驾驶舱

### G1. 页面目标

新增或重构“自主决策”页面，使评委在 30 秒内看懂：

- 当前瓶颈在哪里；
- 系统正在比较哪些选择；
- 为什么选择当前方案；
- 计划与实际是否偏离；
- 安全屏障是否介入；
- 当前方案距离参照最优值有多远。

### G2. 必要组件

1. **数字孪生状态条**：订单、WIP、炉批、故障和计划版本。
2. **计划/实际甘特图**：Arm1、Arm2、Arm3、物流、S4 和炉体。
3. **决策候选表**：候选动作、资源、总成本和成本分解。
4. **拒绝原因表**：前驱、能力、工具、工位、下游容量、路线或安全冲突。
5. **最优性面板**：CP-SAT 目标、下界、在线目标和 gap。
6. **安全面板**：最小净空、预约冲突、等待位置和重规划次数。
7. **预测校准面板**：预计时长、实际时长和预测误差。

### G3. 交互原则

- UI 不直接修改任务状态；
- 所有数据显示来源时间和计划版本；
- 不再增加尚未实现但看似可点击的按钮；
- 未实现能力明确灰置并说明边界；
- 页面刷新不得阻塞 MuJoCo 仿真线程；
- Viewer 和 headless 使用相同后端状态。

## 14. 实验与评估计划

### 14.1 对照算法

| 编号 | 方法 | 用途 |
|---|---|---|
| B0 | 固定顺序/串行基线 | 最弱基线 |
| B1 | 当前动态优先级 | 当前生产基线 |
| B2 | 当前 Beam Search | 局部前瞻基线 |
| P | TwinShield-RH | 提议方法 |
| O | CP-SAT | 小规模最优或有界参照 |

### 14.2 场景矩阵

至少覆盖：

- 单件 A：验证不回退；
- A/B/C 各一件：混流；
- A/B/C 各两件：六托盘高负载；
- 6～12 个排队订单：WIP 与释放控制；
- 紧急订单中途加入；
- Arm3 检测与安装竞争；
- 炉批未满、等待超时和交期风险；
- 钎料漏涂、翅片抓取失败、翅片位置偏差；
- 一台机器人暂时离线；
- 运输或工位延迟。

### 14.3 随机设计

- 每个随机场景至少 20 个种子，目标 30 个；
- 订单到达、产品组合、交期松紧和代表性故障位置随机化；
- 所有方法共享相同场景种子；
- 失败、超时和安全停机必须计入结果，禁止只保留成功样本。

### 14.4 核心指标

- makespan；
- 吞吐量；
- 平均流动时间；
- 加权延期与按期交付率；
- Arm1/Arm2/Arm3 利用率；
- 工位阻塞和机器人饥饿时间；
- 工具切换和产品设置时间；
- WIP 与炉批等待；
- 故障恢复成功率和恢复时间；
- 在线决策 p50/p95/max 延迟；
- CP-SAT 最优性差距；
- 最小预测净空、预约冲突和非预期接触；
- 仿真墙钟、RTF 和内存开销。

### 14.5 消融实验

每次只关闭一个因素：

- 无在线时长更新；
- 无关键路径项；
- 无下游阻塞项；
- 无工具/产品设置成本；
- 无炉批前瞻；
- 单安装资源；
- 无替代路线；
- 安全屏障影子模式与强制模式。

安全屏障消融只用于分析计划冲突，禁止执行已知不安全轨迹以换取更短节拍。

### 14.6 统计方法

- 报告均值、中位数、标准差和 95% 置信区间；
- 对配对种子结果使用配对检验或 bootstrap；
- 同时报告绝对值和相对改善；
- 不用单次最好结果代表算法性能；
- 原始 CSV/JSONL、配置、种子和提交号一并保存。

### 14.7 量化验收目标

| 指标 | 目标 |
|---|---:|
| 六订单高负载 makespan，相对 B1 | 平均下降 ≥ 10% |
| 加权延期，相对 B1 | 平均下降 ≥ 20% |
| 下游阻塞时间，相对 B1 | 平均下降 ≥ 15% |
| 单件场景节拍回退 | ≤ 3% |
| 在线决策延迟 | p95 < 50 ms |
| 小规模在线方案相对 CP-SAT gap | 目标 ≤ 5%，上限 ≤ 10% |
| 非白名单接触 | 0 |
| 关键自由运动预测净空 | ≥ 40 mm |
| 故障闭环完成率 | 100% |
| 0.25×～32× 结果一致性 | 100% |

若某项未达到，报告必须保留真实结果并解释瓶颈，不能调整口径掩盖负结果。

## 16. 分阶段迁移与门禁

### Phase 0：冻结事实基线

完成 A 工作流。没有可靠基线，不进入算法替换。

**门禁**：现有测试通过，关键实验可复现，事件日志完整。

### Phase 1：影子数字孪生

新增快照、时长估计和决策记录，但不改变现有派工。

**门禁**：影子预测与运行时状态一致，不影响现有结果和 RTF。

### Phase 2：CP-SAT 参照层

完成离线/旁路求解和计划校验，仍不控制物理流程。

**门禁**：小规模计划合法，可报告 objective、bound 和 gap。

### Phase 3：在线调度影子比较

TwinShield-RH 与现有调度器并行计算，只记录“如果由新算法决策会怎样”。

当前已接入 `TwinShieldShadowScheduler` 和 `compute_shadow_schedule()`：它读取同一
`DigitalTwinSnapshot`，生成下一安全窗口候选、完整贪心前瞻、拒绝原因以及与 CP-SAT
目标的相对 gap；不会改任务状态、资源预留或 MuJoCo actor。可用
`benchmarks/run_shadow_comparison.py`复现。当前门禁仍要求进入下一阶段前用多种子记录
决策延迟和饥饿情况，不能把影子目标当作实际 makespan。

**门禁**：无非法任务、无明显饥饿、决策延迟达标。

### Phase 4：在线调度成为 V2 权威策略

只替换任务选择，不替换物理 actor。

当前已由 `TwinShieldAuthority` 对规划快照和实时提交状态执行双重校验，V2 默认使用
`AUTHORITY`，操作员可用 `FALLBACK` 无损恢复当前动态调度器。承诺窗口采用两阶段原子
预留/启动，失败时取消已启动技能并释放托盘、运动、资源和区域状态。调度只在 READY、
资源、工位或区域事实变化时重算，并报告 p50/p95/max 决策延迟。

2026-08-22 A/B/C 完整 MuJoCo headless 对照中，两种模式均完成 3/3：TwinShield 为
167.55 s，回退基线为 167.60 s。该结果证明接管与回退路径可用，但仅有约 0.03% makespan
改善，尚未达到六订单平均下降 10% 的最终算法目标，不能夸大为显著提速。

六订单 `A,B,C,A,B,C` 权威模式完成 6/6，makespan 为 270.35 s；决策 p95 为
42.99 ms、最大 45.82 ms，达到本阶段延迟门禁。原始 JSON 位于
`benchmarks/results/2026-08-22-phase4/`。

**门禁**：单件不回退，多订单完成率 100%，所有回退路径有效。

### Phase 5：几何安全屏障影子模式

记录真实几何冲突、最小净空和预约冲突。

**门禁**：白名单稳定，无大量误报，性能开销可接受。

### Phase 6：安全屏障逐段强制

先接管跨工位自由运动，再覆盖共享空间；工艺接触段最后处理。

**门禁**：非预期接触为 0，故障/reset 后无预约泄漏。

### Phase 7：V2 柔性路线与驾驶舱

接通真实可执行 Alternative，完成 UI 决策证据链。

**门禁**：UI 每个展示项都能追溯到真实后端数据。

### Phase 8：冻结竞赛版本

停止新增功能，只运行实验、修复回归、制作报告和视频。

## 20. 风险登记

| 风险 | 影响 | 控制措施 |
|---|---|---|
| CP-SAT 模型规模过大 | 在线求解超时 | 小窗口、严格时限、保存 incumbent、确定性回退 |

| 新调度破坏成熟物理轨迹 | 流程回归 | 只替换任务选择，不立即替换工艺 actor |
| UI 阻塞仿真线程 | RTF 和交互下降 | 后端快照、限频刷新、图表增量更新 |
| 实验只对特定种子有效 | 答辩可信度不足 | 配对多种子、置信区间、公开失败样本 |
| 自定义订单超出物理能力 | 场景状态损坏 | 计划阶段严格拒绝，禁止半接纳 |
| 临近提交仍增加功能 | 无法冻结稳定版本 | 09-10 后停止新增非关键功能 |
