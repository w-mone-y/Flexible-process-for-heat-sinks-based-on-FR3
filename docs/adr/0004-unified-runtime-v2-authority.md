# ADR-0004: 冻结 V1 并将统一制造运行时作为 V2 权威控制器

## Status

Accepted

## Context

V1 已形成稳定的单安装支路物理基线。V2 已具备双安装支路、六托盘、贯通式
三层炉、故障闭环和完整 MuJoCo actor，但当前 `DualLineRuntime` 同时承担订单、
派工、物流和物理 actor 编排，`ManufacturingRuntime` 则独立维护任务 DAG、能力
绑定和动态调度。这会产生两个都能推进订单的逻辑权威，任务图状态与物理动作也
可能发生先后不一致。

## Decision

- V1 从提交 `91244c1` 起冻结为回归与效率比较基线；除缺陷修复和兼容性测试外，
  不再向 V1 增加竞赛功能。
- V2 是唯一竞赛演示和后续创新主线。
- `ManufacturingRuntime` 是订单、任务 DAG、READY 释放、资源/区域预留、AND/OR
  路由、动态调度、恢复插链和完成状态的唯一逻辑权威。
- `DualLineRuntime` 逐步收缩为 V2 物理执行适配器；它不得在没有统一运行时许可时
  启动新动作，也不得用预计时长向统一运行时宣告完成。
- 统一物理技能接口保持非阻塞 `start → update/poll → cancel`。物理技能只有在
  MuJoCo 反馈证明末端/托盘/炉门等相关条件全部到位并停稳后才能返回成功；预计
  时长只用于超时、调度评分和 UI 进度，不是完成证据。
- 物理完成事件必须包含任务、资源、仿真时间、反馈来源和已通过的完成条件，供
  任务图、指标和故障恢复共同消费。
- 迁移按纵向切片进行：单个 A 订单、A/B/C/D 与合法自定义订单、多订单及
  AND/OR 分支、全局动态调度。每个切片通过后才扩大下一层范围。

## Invariants

- 任一载件托盘始终只有一个所有者，除空托盘虚拟返回外不得瞬移。
- 逻辑任务不得早于对应物理技能变为 `SUCCEEDED`。
- 相同订单、种子和故障场景在 0.25×～32× 下具有相同任务结果。
- Arm3 检测优先，已开始的单片翅片安装不可抢占。
- 合流、S4、炉口和输出区必须先预留，再发生物理运输。
- 不兼容产品不得混炉，已锁定炉批不得被紧急订单拆分。

## Consequences

- V2 控制链只保留一个可解释的逻辑权威，UI、headless、实验和 MuJoCo Viewer
  消费同一任务状态。
- 现有 V2 actor、轨迹和场景几何可以继续复用，但每个动作必须经过物理技能适配
  接口，迁移期间不得用修改展示标志来伪装接通。
- `DualLineRuntime` 的旧公共接口在迁移期由兼容门面保留；新代码不得继续直接在
  UI 或入口中增加第二套订单推进逻辑。
