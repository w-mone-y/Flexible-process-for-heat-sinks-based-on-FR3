### 恢复机制与物理返工

V1 通过**图手术**恢复：往 `TaskGraph` 里插入返工任务、改接依赖边。
V2 没有 DAG，它推进的是每件产品的 `UnitStage` 状态机，因此恢复改为**阶段回退**。

当前质量故障采用两阶段触发：生产操作只创建 `PhysicalFaultState`，相机完成
采集与分析后才创建 `FaultRecord` 和 `V2RecoveryPlan`。因此缺陷不会在“修复开始”
时突然出现。返工使用受托盘所有权约束的反向物理边，不允许只回退状态机：

漏涂返工有一个额外不变量：返回 S2A 时，完整钎料排版和所有已完成焊道必须保留。
Arm2 只沿目标 `braze_XX` 的缺失后 64% 运行局部轨迹；相邻焊道不隐藏、不缩短、
不重涂。缺陷几何每帧都从捕获的原始尺寸计算，禁止把上一帧结果再次乘比例。

### 四种扰动模型

不是所有故障都能用同一种方式建模，这一点也踩过坑：

1. **实体返工**（钎料与翅片质量类）——托盘沿受约束的反向物流边回到原工位，
   只修目标缺陷，再回检测工位复检。
2. **资源隔离**（`ARM_UNAVAILABLE`）——冻结当前机械臂的逻辑时钟和 MuJoCo
   关节播放；到期或手动恢复后从原轨迹继续，无关资源继续工作。
3. **当前工序保持**（升降、推叉、炉门互锁）——冻结故障发生的当前工序及其
   物理运动，恢复后完成安全复位/互锁复核并继续，绝不把延时错误计到下一工序。
4. **安全隔离或替代分配**——料架坏层改派其他空层但保留坏层隔离；接触停机与
   托盘归属不一致必须由操作员确认，计时器和“自动恢复”选项不能绕过安全门。

第 3 类为何不用简单资源拒绝：几个炉体分支在调用 `_start` **之前**就提交了物理状态
（`close_front`、`open_rear`、`mark_product_removed`）。若此时拒绝启动，
炉体模型与状态机会失配。因此故障绑定到已经提交的当前 `_Operation`，用独立
`fault_hold_remaining_s` 冻结它；恢复计划只在该操作真实完成后转为成功。

相应地 `_start()` 遇到被隔离资源时**返回 False 而非抛异常**——
有八条 `_start` 调用路径未经 `_operation_start_allowed` 把关，
被隔离的机构应当让产线停等，而不是让 tick 崩溃。

### 全故障恢复矩阵

| UI 故障 | 物理形成/显示 | 检测或触发 | 正确恢复 | 复检与升级 |
|---|---|---|---|---|
| 钎料局部漏涂 | 涂覆时目标焊道局部缺失 | S2B 焊料相机 | `S2B→S2A`，仅补目标缺口 | 返回 S2B；同一目标最多 2 轮，之后人工 |
| 钎料轨迹偏移 | 目标焊道横向偏移 | S2B 焊料相机 | `S2B→S2A`，目标焊道从一端到另一端逐渐清除，再由 Arm2 整条重涂 | 返回 S2B；最多 2 轮 |
| 翅片抓取失败 | Arm3夹爪保持过大间隙，目标翅片留在料台且托盘对应槽位缺片 | S4 焊前相机 | 托盘保持其余产品状态沿原路返回 S3B，Arm3只重新抓取并补装目标翅片 | 返回 S4 重新检测；通过后自动继续，不进入人工审核 |
| 翅片位置/几何偏差 | 目标翅片独立偏姿 | S4 焊前相机 | `FIN_POSE` 保留 Arm3 自动纠偏；`FIN_GEOMETRY_FAILED` 进入 10 秒人工审核 | 审核完成后继续；两种入口不混淆 |
| Arm 离线 | 指定 Arm 变色且关节原位冻结 | 注入后立即触发 | 三台 Arm 均进入 10 秒人工审核，期间禁止提前解除隔离 | 提示“修改成功✅”后继续原任务 |
| 炉层不可用 | 目标层导轨/锁销变色 | 入炉分层前 | 从可用空层中重新选择 | 改层计划成功；坏层仍隔离至人工修复 |
| 升降/传送超时 | 入炉载体与机构停止、变色 | 装/卸炉当前动作 | 当前动作冻结，安全复位后重试一次 | 当前动作完成才判恢复；再失败人工 |
| 推叉到位超时 | 炉口载体停止、推叉变色 | 装/卸炉当前动作 | 核对托盘唯一归属后恢复当前动作 | 当前动作完成才判恢复；再失败人工 |
| 炉门互锁 | 对应炉门停在当前位并变色 | 开/关门当前动作 | 保持托盘锁定，复核双门/升降/推叉互锁 | 互锁通过前禁止热循环；再失败人工 |
| 炉温曲线异常 | 炉热区异常变色 | 炉后固定相机/质量判定 | 产品保持隔离，转人工工艺评审 | 不自动二次过炉，不进入成品交付 |
| 非预期接触停机 | 关联机构安全色，整线安全保持 | 安全系统立即触发 | 固定等待 10 秒仿真时间模拟人工排除接触 | 提示“修改成功✅”后释放整线保持并继续 |
| 托盘归属不一致 | 输出物流隔离并以安全色提示 | 所有权检查立即触发 | 固定等待 10 秒仿真时间模拟人工核对唯一归属 | 提示“修改成功✅”后释放输出物流并继续 |

`FIN_POSE` 是 UI 对“翅片位置偏差”的友好别名，运行时映射到
`FIN_GEOMETRY_FAILED`，因此目录为 14 个按钮、13 个强类型运行时故障。

## 故障可视化

机制沿用 V1（捕获原始材质/颜色/位姿 → 按效果 id 修改 → 差分还原），
但**几何名表全部重写**。核验方式是逐个故障断言至少命中一个 geom ——
名称表不可信任，选择器命中零个会**静默失败**：操作员看不到颜色变化，
会以为故障没触发。

两处必须用 `bodies` 而非 `prefixes`：炉层与炉门在 MJCF 中是 body，
其 geom 未命名。这也是靠核验发现的（初版三个故障零命中）。

质量类不再整盘着色：漏涂只缩短目标 `braze_XX` 的缺失部分，偏轨只偏移目标焊缝，
抓取失败使目标翅片缺席，姿态故障只横向平移目标 `fin_XX`。
局部返工按进度逐步恢复目标几何，邻近焊道/翅片保持不变；复检通过后关闭恢复计划。
设备故障则同时修改机构颜色和运动状态，不只展示一条形式化记录。

## 控制台接通

| 此前状态 | 现在 |
|---|---|
| `faults_v2` / `recoveries` / `manual_fault_requests` 硬编码空列表 | 真实快照 |
| `ui_capabilities.fault_injection = False`，注入台整体禁用 | `True`，可用 |
| 恢复动作四按钮 V2 下禁用 | 可用（暂停/继续/重试/转人工） |
| 「实时甘特图」页恒空 | 由 `OPERATION_STARTED/COMPLETED` 事件投影 |
| 任务图只在错误页签索引刷新且整图清空重绘 | 当前页每 250 ms 原位更新节点、物理路点进度和时间戳 |
| 指标页四个 key 全缺失（恒显示 0） | makespan / 吞吐 / 利用率 / 恢复率 全部计算 |
| `fixture` 显示「待接入 V2 物理夹具」 | 按订单 preset 显示真实梳齿模块与压紧力 |
| `zone_locks` 恒空 | 由托盘唯一归属导出（V2 用归属实现互斥） |
| `max_parallel_arms` 恒 0 | 由事件日志重建历史峰值 |
| 工位筛选六个下游工位无法选择 | `station_titles` 与任务实际 `station_id` 对齐 |
| `preferred_rack_layer` / `route_strategy` 静默丢弃 | **明确报错**并说明未生效原因 |

最后一条是刻意的取舍：**静默忽略一个设置比明确拒绝更糟**。
订单仍会被接受，但操作员会看到「以下设置在 V2 下未生效：…」。

## 新增「柔性总览」页签

`GET /flexibility` 返回六个柔性维度，每个都带状态、关键指标与依据。
状态只有 `FULL` / `PARTIAL` / `NONE`，且 `PARTIAL` 是**诚实使用**的：

| 维度 | 状态 | 关键指标 |
|---|---|---|
| 产品柔性 | 已实现（规划） | 4 种 YAML 产品；V2 实体执行明确标注为 A/B/C 三种 |
| 工艺柔性 | **部分实现** | 2 道工序有替代路线，但调度器尚不自主择优 |
| 资源柔性 | **部分实现** | 翅片安装真实选择 Arm1/Arm3；其余多候选仍属编译结果 |
| 批量柔性 | 已实现 | 六托盘 WIP + 三层炉批 |
| 换型柔性 | **部分实现** | 同族排序减少 43.0%，但人工基线为占位值 |
| 扰动柔性 | 已实现 | 14 种故障可注入，恢复率实测 |

该页签为按需刷新（重新加载配置并编译工艺路线），不挂在 250 ms 轮询上。

## 边界

- V2 九个单段按钮仍永久灰置：物理 actor 未接通，点击会明确报错而非假装成功。
- 自定义产品订单在 V2 下仍不支持（`custom_orders: False`），会明确提示。
- 逐条焊缝/翅片物理缺陷已接入；设备故障仍以机构着色和运动保持表达。
- 手动重规划按钮在 V2 下禁用并附说明：V2 调度器每 tick 自动重算。
