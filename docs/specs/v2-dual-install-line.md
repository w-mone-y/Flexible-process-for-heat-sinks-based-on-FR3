# V2 双安装支路柔性钎焊产线

## Status / Acceptance Boundary

当前交付是 **V2 Phase 1 物理门控预演版**。已验收范围为 A/B/C 订单、六托盘
连续载具运输、Arm1/Arm3 双安装支路、真实 FR3 关节与工具 TCP 到位门控、
Y 形合流、三位炉前缓存、三层前装后卸批次炉、固定焊后检测、虚拟空托盘回流，
以及与 V1 共用的十页签 Qt 控制台。紧急订单、ISO-8601 交期、交期风险部分炉批
和双支路成本解释也进入运行时与 UI。

本阶段不称为“完全物理最终版”。自定义产品订单、V2 单段物理 actor、物理故障
注入/恢复 actor、独立固定视觉产品池和由滑轨执行器直接驱动的全部载货托盘，
留待 Phase 2。运行时继续通过 `execution_mode=CONTROL_PLANE_REHEARSAL` 和
`physical_execution_complete=false` 公开这一边界。

## Problem Statement

当前 V1 只有一条翅片安装支路，Arm1 逐片安装时长期成为多订单瓶颈。
Arm3 大部分时间只执行检测，无法在检测空闲窗口帮助安装。当前三托盘对象池在
三层炉批运行时也会耗尽，使所有上游机械臂在炉体长周期内没有托盘可继续加工。

用户需要一套独立于 V1 的 V2 场景：Arm3 增加固定窄型夹爪，在独立的翅片台和
安装台帮助 Arm1 并行安装；两条安装支路连续合流到共享检测台；合格托盘经过
炉前缓存进入三层、前门装载和后门卸载的批次 CAB 炉；焊后经固定视觉门架分级
并进入成品出口。多订单必须由真实物理状态驱动动态分流和兼容拼炉，而不是只在
任务图上显示并行。

## Solution

新增一个独立 V2 启动入口和对应 MuJoCo 场景，保留 V1 不变。V2 使用沿世界
坐标正 X 方向流动的双支路拓扑：基板上料、钎料涂覆和焊料检测后，托盘动态
分配到 Arm1 安装线 A 或 Arm3 安装线 B；两条支路通过单占用 Y 形合流机构进入
共享焊前检测台；随后进入三位炉前缓存和三层贯通式批次炉；炉后固定视觉门架
完成最终分级并送入成品出口。

V2 预分配六套托盘，形成“炉内三件＋上游下一批三件”的双批 WIP。Arm1 是
专职安装资源，Arm3 使用固定相机/窄夹爪复合末端并以检测优先方式兼职安装。
安装分流按预计最早完成时间计算，考虑翅片数量、机械臂可用时间、队列、交期、
优先级和 Arm3 检测预约。兼容 A/B/C 产品可以跨订单拼炉；满炉、等待
超时或交期风险触发炉批。成品移除后，空托盘只在状态机中虚拟返回，不建设视觉
返回输送线。

## User Stories

1. 作为操作者，我希望通过独立 V2 入口启动新场景，以便随时返回稳定的 V1 基线。
2. 作为操作者，我希望 V2 Phase 1 使用与 V1 相同的 A/B/C 订单配置，以便直接比较两版产线。
3. 作为操作者，我希望场景沿单一物流方向清晰排布，以便从画面中理解每道工序。
4. 作为调度器，我希望焊料检测通过后才释放安装分流任务，以便不让不合格托盘进入安装支路。
5. 作为调度器，我希望将托盘分配到预计最早完成的安装支路，以便降低多订单总完工时间。
6. 作为调度器，我希望为每次安装分配提供成本和阻塞原因，以便 UI 能解释决策。
7. 作为 Arm1，我希望专职处理安装线 A 的翅片，以便持续服务长订单。
8. 作为 Arm3，我希望在没有检测任务时帮助安装线 B，以便利用检测空闲窗口。
9. 作为 Arm3，我希望固定安装相机和窄型夹爪，以便无需换刀即可在安装与检测间切换。
10. 作为 Arm3，我希望分别使用夹爪 TCP 和相机 TCP，以便两个任务都保持正确位姿。
11. 作为 Arm3，我希望当前单片安装动作不可抢占，以便携带翅片时不会突然切换任务。
12. 作为 Arm3，我希望检测台即将到达托盘时停止领取下一片翅片，以便共享检测不长期堵塞。
13. 作为产品单元，我希望始终绑定唯一托盘，以便跨工位移动时不丢失订单和质量状态。
14. 作为托盘，我希望任一时刻只有一个所有者，以便不发生重复挂载或物理分身。
15. 作为安装线 A，我希望拥有独立翅片台和安装台，以便不与安装线 B 争用几何空间。
16. 作为安装线 B，我希望拥有独立翅片台和安装台，以便与 Arm1 真正并行工作。
17. 作为输送系统，我希望载货托盘在物理门控的连续载具轨迹上移动，以便画面中不出现瞬移。
18. 作为合流控制器，我希望合流区一次只允许一套托盘进入，以便两条支路不会重叠穿模。
19. 作为后到托盘，我希望停在本支路缓存位，以便共享检测台释放后再安全进入。
20. 作为共享检测台，我希望托盘到位和停稳后才允许 Arm3 扫描，以便检测姿态稳定。
21. 作为共享检测台，我希望产品长方形边缘与相机画面平行，以便检测展示清晰。
22. 作为炉前缓存，我希望容纳下一炉最多三件托盘，以便炉体工作期间上游仍可生产。
23. 作为炉批规划器，我希望只组合工艺兼容产品，以便混炉不会破坏产品配方。
24. 作为炉批规划器，我希望三层装满时立即启动，以便降低炉体空闲。
25. 作为炉批规划器，我希望等待超时或交期风险时启动部分炉批，以便小订单不会无限等待。
26. 作为紧急订单，我希望影响下一次未锁定炉批，以便提高准时率。
27. 作为已锁入炉批的托盘，我希望不被紧急订单替换，以便保持物理所有权和安全。
28. 作为炉体，我希望前门只用于装载、后门只用于卸载，以便产品全程保持方向不变。
29. 作为炉体，我希望三层托盘锁定、机构退出且托盘静止后才启动，以便满足安全互锁。
30. 作为炉体，我希望真实等效工艺时间与 MuJoCo 演示时间分离，以便指标不会误导。
31. 作为研究者，我希望把真实等效 CAB 周期暂定为 60 分钟，以便进行可解释的调度实验。
32. 作为观众，我希望在约 30 秒演示周期内看见预热、升温、钎焊和冷却，以便理解炉体状态。
33. 作为炉后检测系统，我希望使用固定视觉门架完成分级，以便不要求 Arm3 跨越整条产线。
34. 作为成品，我希望从炉体后门直接进入成品出口，以便不逆流穿过生产区域。
35. 作为空托盘，我希望成品移除后通过虚拟返回恢复到上料缓冲区，以便不增加视觉回线。
36. 作为操作者，我希望 UI 显示六套托盘、两个安装支路、合流、炉前缓存和三层炉位，以便理解实时物流。
37. 作为操作者，我希望 UI 显示 Arm3 当前处于安装还是检测，以便理解资源切换。
38. 作为操作者，我希望暂停和继续保持所有托盘所有权与动作进度，以便安全恢复。
39. 作为操作者，我希望 reset 释放全部 V2 约束并恢复六托盘和双门炉体，以便重复演示。
40. 作为实验者，我希望 V1 与 V2 在相同订单和种子下运行，以便量化安装并行带来的改善。
41. 作为实验者，我希望至少观测到一段 Arm1 与 Arm3 同时安装的物理时间，以便证明并行不是任务图假象。
42. 作为维护者，我希望 V2 失败不改变 V1 入口和场景，以便降低重构风险。
43. 作为维护者，我希望 MJCF 名称和公共状态具有契约测试，以便场景修改不会静默破坏后端。
44. 作为维护者，我希望不可见托盘关闭碰撞并停放在隔离位，以便控制六套产品池的物理开销。
45. 作为维护者，我希望 0.25× 到 32× 只改变推进速度，以便任务结果与调度依赖保持一致。

## Implementation Decisions

- V2 是独立入口，不覆盖 V1。
- V2 的权威布局对象统一保存全部工位、机械臂、支路、缓存、炉体和出口坐标。
- V2 物流拓扑为上料、涂覆、焊料检测、双安装分支、单合流、共享焊前检测、
  炉前缓存、三层炉、炉后检测和成品出口。
- Arm3 采用固定复合末端，夹爪位于法兰中心，相机侧向偏置并使用独立 TCP。
- Arm3 的资源策略为检测优先、单片安装不可抢占。
- 安装分流使用可解释的预计最早完成时间成本，而不是固定轮流。
- 六套托盘形成两个最大三件炉批的 WIP 上限。
- 合流区、共享检测台、炉前缓存和炉口都必须先原子预留。
- 炉批兼容性至少检查材料体系、气氛、温度、保温、产品高度和层位。
- 炉批满三件立即启动；等待超时、交期风险或没有更多兼容产品时允许部分炉批。
- 炉体前门装载、后门卸载，托盘全程不旋转。
- 炉后质量分级由固定视觉门架执行。
- 空托盘虚拟返回是唯一获准不显示连续物理路线的托盘转移。
- 真实等效工艺时间与演示时间分离，默认分别为 3600 秒和 30 秒。
- V2 状态扩展包含拓扑、安装分配、六托盘、合流、炉批、双门、炉后检测和虚拟返回。

## Testing Decisions

- 测试只通过已确认的公共边界观察行为，不断言私有方法或内部协作者调用。
- V2 独立启动入口是最高层端到端接缝。
- 布局拓扑公共对象验证合法工位图、坐标和支路关系。
- 安装分流公共接口验证 Arm1/Arm3 选择、检测预约、优先级和可解释原因。
- 托盘流公共接口验证唯一所有权、连续物理移交和虚拟返回。
- 炉体公共接口验证兼容拼炉、部分炉批、层位顺序和双门互锁。
- MJCF 契约验证三台机械臂、Arm3复合末端、六托盘、双支路、合流、缓存、
  三层炉、双门、炉后相机及全部执行器和约束。
- Headless 集成测试验证多订单物理门控预演并行、一次共享炉周期和最终成品交付。
- 版本基准用实际完工事件分别统计仿真 makespan、吞吐和墙钟耗时，不使用调度估值。
- 现有 XML 契约、物理 actor、旧入口和全套回归测试作为 V1 先例和冻结基线。
- 每个实现切片遵循一个失败测试、最小通过实现的红—绿循环。

## Out of Scope

- 不重写 FR3 底层关节控制器或逆运动学求解器。
- 不引入强化学习作为首版调度器。
- 不建设视觉可见的空托盘返回输送线。
- 不模拟真实熔池、润湿、冶金组织、热传导或结构强度。
- 不把当前炉温参数宣称为生产认证配方。
- 不增加第四台机械臂。
- 不支持超过六套物理托盘或单炉超过三件。
- 不删除或替换 V1。
- Phase 1 不支持 V2 自定义产品订单；V1 柔性订单入口继续保留。
- Phase 1 不提供 V2 单段、物理故障注入/恢复 actor。
- Phase 1 的载货托盘使用连续 mocap 载具与可见机构联动；不宣称所有托盘均由
  独立 slide joint/actuator 直接驱动。

## Further Notes

- 当前产品配置没有指定铝合金、钎料、钎剂和炉体功率，因此 60 分钟是可解释的
  CAB 调度假设，不是生产工艺保证。
- V2 候选坐标必须在实现时通过关键姿态可达性、关节余量和碰撞预检，不能仅凭
  平面距离批准。
- 六套产品池必须通过不可见几何停放和碰撞关闭控制性能。
