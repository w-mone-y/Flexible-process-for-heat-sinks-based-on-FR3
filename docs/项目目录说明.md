# 项目目录说明

本文档说明 GitHub 仓库中主要文件和目录的职责，帮助后续从 `v1.0.0`
baseline 建立功能分支时快速找到正确的修改位置。

## 推荐阅读顺序

1. `README.md`：了解产线目标、运行方式和当前能力。
2. `brazing_line.py`：查看主程序、命令处理、仿真循环和 UI/API 接入。
3. `brazing_sim/manufacturing_runtime.py`：查看多订单任务图调度与恢复运行时。
4. `brazing_sim/planning/task_graph_builder.py`：查看订单如何转换成制造任务 DAG。
5. `brazing_sim/execution/async_line_skills.py`：查看 Arm1/2/3 和工位任务的物理动作。
6. `brazing_line.xml`：查看 MuJoCo 主场景、机械臂、工位和输送机构。
7. `tests/`：通过回归测试理解各项行为约束。

## 顶层入口与场景

| 路径 | 作用 |
|---|---|
| `brazing_line.py` | 当前主程序入口；负责 MuJoCo 仿真循环、UI/API、订单命令和 V2 运行时接线。 |
| `brazing_line.xml` | 当前标准版 MuJoCo 主场景；包含三台 FR3、S1/S2A/S2B/S3、炉体、料架和成品出口。 |
| `run_flexible_order.py` | YAML 柔性订单、批量订单、dry-run、headless 和调度实验入口。 |
| `brazing_line_cinematic.py` | 电影级展示版本入口；复用标准版物理逻辑。 |
| `brazing_line_cinematic.xml` | 电影级场景包装层；加载标准场景并叠加纯视觉细节。 |
| `README.md` | 项目总说明、安装方法、运行命令、工艺流程和接口说明。 |
| `Makefile` | 常用安装、测试、格式检查和启动命令。 |
| `pyproject.toml` | Python 包元数据、依赖与开发工具配置。 |

## 核心 Python 包：`brazing_sim/`

### 运行时与领域

| 路径 | 作用 |
|---|---|
| `manufacturing_runtime.py` | 多订单统一运行时；管理订单队列、DAG、调度、资源、故障和恢复。 |
| `domain.py` | 产品、翅片、路径、夹具和订单阶段等核心领域状态。 |
| `events.py` | 结构化事件总线与运行事件类型。 |
| `resources.py` | 旧流程兼容资源租约；V2 资源管理位于 `scheduling/`。 |
| `workcells.py` | 异步工位、托盘所有权、输送段和路线状态模型。 |
| `layout.py` | 浅 U 形产线权威坐标及原料翅片单层布局规则。 |

### 物理执行：`brazing_sim/execution/`

| 路径 | 作用 |
|---|---|
| `async_line_skills.py` | Arm1/2/3、梳齿、压紧和四段输送的连续物理技能。 |
| `async_line_logistics.py` | 入炉、炉内停留、出炉、检测位和成品出口的可见物流技能。 |
| `skill_registry.py` | 将制造任务类型映射到具体技能实现。 |
| `skill_executor.py` | 在同一仿真 tick 中推进多个非阻塞技能。 |
| `execution_monitor.py` | 技能进展、超时和无进展监测。 |

### 柔性订单：`brazing_sim/flexible/`

| 路径 | 作用 |
|---|---|
| `models.py` | 产品、订单、配方、工装、料架和 `ProcessPlan` 强类型模型。 |
| `loader.py` | 严格 YAML 加载与中文字段错误报告。 |
| `geometry.py` | 根据订单参数生成翅片目标和钎料路径。 |
| `planner.py` | 将配置文件转换成可执行 `ProcessPlan`。 |
| `multi_order.py` | 多订单文件、UI 临时订单和自定义产品计划。 |
| `preflight.py` | 执行前检查对象池、工装、喷嘴、层位和场景契约。 |

### 任务规划：`brazing_sim/planning/`

| 路径 | 作用 |
|---|---|
| `task_models.py` | 制造任务类型、状态、中文名称和任务数据。 |
| `task_graph.py` | DAG 依赖、READY 释放、失败阻塞和动态分支。 |
| `task_graph_builder.py` | 将每个 `ProcessPlan` 展开为完整工艺与物流 DAG。 |
| `batch_planner.py` | 炉批兼容性与候选托盘选择逻辑。 |
| `motion_planner.py` | PRM/A*、RRT-Connect 和时空预约基础实现。 |
| `workcell_motion.py` | 面向当前三机械臂工位的运动规划接入层。 |
| `task_validator.py` | 制造任务字段及依赖约束检查。 |

### 动态调度：`brazing_sim/scheduling/`

| 路径 | 作用 |
|---|---|
| `dynamic_priority_scheduler.py` | 根据时间、优先级、工具和区域选择并行任务。 |
| `fixed_sequence_scheduler.py` | 保留旧顺序的固定调度基线。 |
| `resource_manager.py` | 机械臂、输送、炉体和料架资源状态及原子预留。 |
| `zone_lock_manager.py` | 共享工位和扫掠区域互斥租约。 |
| `scheduling_cost.py` | 动态派工成本及权重分解。 |
| `event_bus.py` | 调度层事件发布与订阅。 |

### 故障恢复：`brazing_sim/recovery/`

| 路径 | 作用 |
|---|---|
| `fault_models.py` | 故障记录、恢复计划和恢复步骤模型。 |
| `recovery_policy.py` | 漏涂、翅片、资源、输送和炉门故障的恢复策略。 |
| `replanner.py` | 故障后的 READY 集合、资源和层位重规划。 |
| `retry_manager.py` | 重试次数、等待和人工复核控制。 |

### 实验与指标：`brazing_sim/experiments/`

该目录包含 headless 实验运行、事件指标计算、fixed/dynamic 对比以及
JSON/CSV/Markdown 报告导出。所有指标来自实际仿真事件时间戳。

### 其他重要模块

| 路径 | 作用 |
|---|---|
| `scene.py` | MuJoCo 模型注册、对象池、weld、可见性和动态几何配置。 |
| `motion.py` | FR3 控制器、IK、姿态和运动轨迹基础能力。 |
| `actors.py` | 旧单流程的机械臂及工艺 actor，继续支持分段演示。 |

| `batch.py` / `batch_transfer.py` | 三层批次和托盘转运兼容流程。 |
| `inspection.py` / `quality.py` | Arm3 检测几何、真值判定和焊后分级。 |
| `safety.py` | 接触监测、允许接触和非预期碰撞安全停机。 |
| `fixture.py` | 梳齿、短压梁、压紧和夹具锁定控制。 |
| `furnace.py` / `conveyor.py` | 炉体热循环与旧输送流程兼容实现。 |

## 兼容与实验代码

根目录中的 `base_develop*`、`flexible_pick_place*`、`multi_arm_line*`、
`diffik*`、`grasp_*`、`object_manager.py`、`skill_library.py` 等文件是项目
演进过程中保留的独立实验或旧入口。当前功能开发应优先修改
`brazing_line.py`、`brazing_line.xml` 和 `brazing_sim/`，除非任务明确要求
维护 legacy 示例。

## 不应提交的生成内容

`.gitignore` 已排除 Python 缓存、pytest/Ruff 缓存、覆盖率、构建目录、
`.DS_Store` 和 `*.egg-info`。运行时实验输出应放在临时或明确的结果目录，
不要把大体积 viewer 截图、视频、虚拟环境和本机密钥提交到仓库。
